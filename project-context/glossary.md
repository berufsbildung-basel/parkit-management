# Project Glossary

Definitions of key terms used in the P.A.R.K.I.T project.

## Project & Management

| Term | Definition |
|---|---|
| **P.A.R.K.I.T** | Application for reserving office parking spaces. |
| **Workstream** | A specific area of work within the project. |
| **Scope** | Work and functionality included in the project. |
| **Requirement** | A condition or capability the system must satisfy. |
| **Use Case** | A description of how a user interacts with the system to achieve a goal. |
| **Constraint** | A limitation that affects the project or its implementation. |
| **Assumption** | Something considered true but not yet confirmed. |
| **Dependency** | Something required before another activity can proceed. |
| **Risk** | A possible event that could negatively affect the project. |
| **Mitigation** | An action intended to reduce a risk or its impact. |
| **Stakeholder** | A person or group affected by or involved in the project. |
| **Milestone** | An important checkpoint in the project. |

## Research & Development

| Term | Definition |
|---|---|
| **Architecture** | The main system components and how they connect and communicate. |
| **Architecture Option** | A possible technical design being evaluated. |
| **Evaluation Criteria** | Factors used to compare possible solutions. |
| **Proof of Concept (PoC)** | A small test to verify whether a technical approach is feasible. |
| **Integration** | Connecting different systems or components so they work together. |
| **Scalability** | The ability to support growth without major redesign. |
| **Reliability** | The ability of a system to operate correctly and consistently. |
| **Deployment** | Making a system available in its intended environment. |

## Software & Communication

| Term | Definition |
|---|---|
| **Backend** | The part of an application that processes data and business logic. |
| **API** | An interface that allows software components to exchange data. |
| **Business Logic** | Rules that determine how the application behaves. |
| **Orchestrator** | A component that coordinates communication and tasks between other components. |
| **Driver** | Software that enables interaction with hardware. |
| **Daemon** | A program that runs in the background to perform ongoing tasks. |
| **MQTT** | A lightweight messaging protocol used for communication between devices. |
| **Ethernet** | A wired networking technology. |
| **Switch** | A device that connects multiple devices within a local network. |
| **Gateway** | A device that connects different networks or communication systems. |
| **LoRa** | Wireless radio technology designed for transmitting small amounts of data over long distances. |
| **LoRaWAN** | A networking protocol that uses LoRa radio communication. |
| **Downlink** | Data sent from the network to an end device. |
| **Firmware** | Software that runs directly on an electronic device. |

## Hardware

| Term | Definition |
|---|---|
| **Raspberry Pi** | A small single-board computer that can run Linux. |
| **Raspberry Pi Pico W** | A microcontroller board with wireless connectivity. |
| **Intel NUC** | A compact computer considered for the orchestrator role. |
| **Interstate 75 W** | A controller board with an integrated Pico W for driving HUB75 LED matrices. |
| **Microcontroller (MCU)** | A small programmable device designed to control hardware. |
| **LED Matrix** | A display made of LEDs arranged in rows and columns. |
| **HUB75** | A hardware interface used to control RGB LED matrix panels. |
| **Power Supply** | A device that provides the required electrical power. |
| **Hardware Compatibility** | The ability of hardware components to work together. |
